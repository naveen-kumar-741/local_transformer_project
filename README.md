# Local Transformer Training Project (Phases 0–15)

A modular PyTorch GPT-style language model project designed for Windows/Linux laptops, including an RTX 3050-class GPU with 4 GB VRAM. It covers a character baseline, BPE tokenizer, GPT training, reproducible checkpoints/logging, dataset preparation, model-size experiments, optimization switches, optional supervised fine-tuning, optional RAG, and optional STT/TTS integration.

## Important hardware reality

- The 10M/30M/70M/100M names are targets, not guaranteed exact sizes. Run `python -m scripts.count_parameters --config configs/10m.json` to see the actual count.
- A 4 GB GPU may only manage small microbatches and short contexts. The 70M/100M configs are stress tests, not promises of practical training speed. Gradient accumulation lowers activation batch size, but does **not** remove the model/optimizer memory cost.
- Start with the included small demo, then run the 10M config. Use a small, legally usable dataset and check the generated text; loss reduction alone does not prove useful language ability.
- Training a model from scratch is not equivalent to a pretrained assistant. Quality depends heavily on tokens, data quality and compute.

## Setup (Windows PowerShell)

1. Install Python 3.10 or 3.11 and a PyTorch build matching your installed NVIDIA driver/CUDA runtime. Follow the official PyTorch selector at https://pytorch.org/get-started/locally/ .
2. Create environment:
   ```powershell
   py -3.10 -m venv .venv
   .\.venv\Scripts\Activate.ps1
   python -m pip install --upgrade pip
   ```
3. Install PyTorch using the command generated by the PyTorch selector, then:
   ```powershell
   pip install -r requirements.txt
   python -m scripts.check_environment
   ```
   If optional speech/RAG packages fail on Windows, install the core dependencies first (`torch numpy tokenizers tensorboard tqdm`) and add optional packages separately.

## Quick start

```powershell
# 1. Put plain text files under data/raw/ (UTF-8; .txt or .md)
python -m scripts.prepare_data --input data/raw --output data/processed --tokenizer char

# 2. Train a tiny sanity-check model first
python -m scripts.train --config configs/demo.json

# 3. Train the first target model
python -m scripts.train --config configs/10m.json

# 4. Generate from a checkpoint
python -m scripts.generate --checkpoint checkpoints/demo/latest.pt --prompt "Once upon a time"

# 5. Inspect parameter count
python -m scripts.count_parameters --config configs/30m.json
```

`prepare_data` creates a tokenizer and packed `train.bin` / `val.bin` token streams. For BPE:
```powershell
python -m scripts.prepare_data --input data/raw --output data/processed_bpe --tokenizer bpe --vocab-size 8000
```
Use the same tokenizer directory when training and generating. Configs are self-contained; edit `data_dir` and `tokenizer_dir` to point to the chosen dataset.

## Main commands

```powershell
python -m scripts.train --config configs/10m.json
python -m scripts.evaluate --checkpoint checkpoints/10m/latest.pt
python -m scripts.generate --checkpoint checkpoints/10m/latest.pt --prompt "The future of science"
python -m scripts.finetune --checkpoint checkpoints/10m/latest.pt --data data/processed
python -m scripts.rag.build_index --docs data/knowledge --index-dir data/rag_index
python -m scripts.rag.chat --checkpoint checkpoints/10m/latest.pt --index-dir data/rag_index
python -m scripts.speech.voice_chat --checkpoint checkpoints/10m/latest.pt
```

## Data and licensing

Only place data you are allowed to use in `data/raw/`. Preserve source, license, document count, preprocessing notes and dataset version in `data/processed/manifest.json`. Keep validation documents separate before tokenization to avoid leakage. The simple starter pipeline uses a deterministic split over sorted documents; for serious experiments, make the split at document/source level before packing.

## Training controls

Edit JSON configs for `batch_size`, `gradient_accumulation_steps`, `block_size`, `max_steps`, `eval_interval`, `save_interval`, `learning_rate`, `weight_decay`, `precision`, `gradient_checkpointing`, and architecture. Training saves model/optimizer/config/RNG state to `checkpoints/<name>/latest.pt`, logs metrics to CSV and TensorBoard, and supports resume with `--resume`.

## Optional components

- Fine-tuning uses next-token supervised training on text. For instruction tuning, prepare examples as text with clear role markers; this starter does not implement preference optimization.
- RAG uses SentenceTransformers + FAISS and injects retrieved snippets into the prompt. It does not update model weights, and a tiny scratch-trained model may fail to follow the context.
- Speech integration uses Faster-Whisper for STT and pyttsx3 for local TTS. Speech models are external pretrained components, not trained from scratch here. Microphone/audio device compatibility varies by OS.

## Troubleshooting

- CUDA OOM: lower `batch_size` to 1, lower `block_size` to 128 or 64, use `precision: "fp16"`, turn on `gradient_checkpointing`, close other GPU apps. For optimizer-state OOM, reduce model size or use a CPU/offloaded optimizer (not included).
- CPU fallback is supported but will be slow for larger configs.
- Resume only from a checkpoint created with compatible model/tokenizer/config.
